Abstract
Simulated environments play an essential role
in embodied AI, functionally analogous to test
cases in software engineering. However, ex-
isting environment generation methods often
emphasize visual realism (e.g.,object diversity
and layout coherence), overlooking a crucial
aspect: logical diversity from the testing per-
spective. This limits the comprehensive eval-
uation of agent adaptability and planning ro-
bustness in distinct simulated environments. To
bridge this gap, we proposeLogicEnvGen, a
novel method driven by Large Language Mod-
els (LLMs) that adopts a top-down paradigm
to generate logically diverse simulated environ-
ments as test cases for agents. Given an agent
task, LogicEnvGen first analyzes its execu-
tion logic to construct decision-tree-structured
behavior plans and then synthesizes a set of
logical trajectories. Subsequently, it adopts
a heuristic algorithm to refine the trajectory
set, reducing redundant simulation. For each
logical trajectory, which represents a poten-
tial task situation, LogicEnvGen correspond-
ingly instantiates a concrete environment. No-
tably, it employs constraint solving for physical
plausibility. Furthermore, we introduce Logi-
cEnvEval, a novel benchmark comprising four
quantitative metrics for environment evaluation.
Experimental results verify the lack of logical
diversity in baselines and demonstrate that Log-
icEnvGen achieves 1.08-2.67x greater diversity,
significantly improving the performance in re-
vealing agent faults by 3.34%–72.00%.

an LLM-driven method that traverses the execution
logic of the agent task to generate logically diverse

manner. To ensure physical plausibility, we formal-

Problem (CSP) and incorporate a constraint solver
to determine object layouts. Following a top-down
paradigm, LogicEnvGen first captures possible task
situations at the abstract logical level and then in-
stantiates them into concrete environments with
varied configurations, thus enhancing logical diver-
sity in environment generation.

generate embodied environments for use as test
cases. Unlike existing benchmarks focusing on

policies (one correct, three faulty). We also intro-

the environments across three dimensions: physical

as test cases. Experimental results demonstrate
that LogicEnvGen generates physically plausible

improves Fault Detection Rate, ranging from 3.34%
to 72.00%. Further evaluations on EMMOE-100
dataset (Li et al., 2025) validate the strong general-

2 Related Work
2.1 Code Test Generation
Code testing, a critical part of software develop-
ment, involves generating various test cases to de-
tect potential bugs and ensure program execution
meets expectations. Existing methods encompass
search-based test generation (Fraser and Arcuri,
2011; Lukasczyk and Fraser, 2022) and symbolic
test generation (Sen et al., 2005). Recently, LLMs
have been employed for automated test generation
(Schäfer et al., 2024; Ryan et al., 2024). Common
evaluation metrics for test generation include accu-
racy, coverage, and bug detection rate (Wang et al.,
2025c; Huang et al., 2024). Inspired by this field,
we conceptualize simulated environments as test
cases and propose a novel method for generating
diverse simulated test cases to systematically eval-
uate embodied agents and reveal potential defects.
2.2 Embodied AI Environment Generation
Early studies mainly rely on manual design (Li
et al., 2024), 3D scanning (Deitke et al., 2023a)
and procedural generation (Fu et al., 2021), which
demand substantial domain expertise and exhibit
limited interactivity. Based on datasets like 3D-
FRONT (Fu et al., 2021), some researchers train
generative models to generate scenes (Tang et al.,
2024a; Wu et al., 2024), which are inherently re-
stricted by the scale and quality of data. Recently,
several studies use LLMs to automatically gener-
ate environments (Wang et al., 2024; Feng et al.,
2023). However, they often allow LLMs to directly
assign object coordinates, which may violate phys-
ical laws like gravity and collision (Jia and Chen,
2024). Some work (Yang et al., 2024c; Littlefair
et al., 2025) formalizes object placement as a con-
straint satisfaction problem. Other text-guided 3D
scene generation works (Zhou et al., 2024, 2025;
He et al., 2023) focus on localized representations
with limited composability, thus restricting their
applicability in embodied AI. These existing meth-
ods emphasize rendering fidelity and visual diver-
sity but overlook logical diversity—a gap that our
method is designed to address.
2.3 LLM for Embodied AI
With rich world knowledge and remarkable reason-
ing capabilities, LLMs are extensively employed
for Embodied AI (Hao et al., 2023). Early work
leverages LLMs as planners to decompose user in-
structions into action sequences (Ahn et al., 2022;
Yao et al., 2023). Some studies generate executable
code to bridge high-level task descriptions and
low-level execution (Liang et al., 2023). Vision-
Language-Action (VLA) models integrate percep-
tion and reasoning into a unified framework for
end-to-end control (Wang et al., 2025d; Fan et al.,
2026). In this work, rather than using LLMs as
planning engines for embodied agents, we utilize
them to construct test cases for simulation.

4 Method
4.1 Overview
In this paper, we propose LogicEnvGen, an LLM-
driven method to generate logically diverse test
cases for the rigorous detection of agent deficien-
cies. Adopting a top-down scheme, LogicEnvGen
captures all potential situations at the abstract log-
ical level and instantiates concrete environments,
enabling coverage of diverse task decision paths.
As shown in Figure 2, it comprises three phases.
4.2 Behavior Plan Derivation
Given an agent task, we utilize LLMs to analyze its
execution logic to derive decision-tree-structured
behavior plans. Specifically, the process includes
three steps: task decomposition, uncertain factor
identification and behavior plan generation.
In contrast to prior work that primarily divides
tasks into sequentially executed subtasks, we de-
compose the embodied task into mutually inde-
pendent subtasks without execution order depen-
dencies. This effectively avoids capturing logi-
cally redundant trajectories. For each subtask, we
identify the associated uncertain environmental fac-
tors affecting the agent execution logic. Subse-
quently, we instruct LLMs to construct a decision-
tree-structured, environment-aware task plan based
on these factors, which outlines distinct agent be-
havior logic under diverse conditions. Represented
in JSON format, its internal nodes are conditional
queriesabout the environment (e.g., “Is the window
open?”) and the edges correspond to theresponses
(e.g., “Yes”). The root-to-leaf decision path defines
a unique logic flow, representing a potential situa-
tion for the subtask. The leaf node encapsulates the
agent execution plan in the corresponding situation.
To ensure the reliability and logical consistency
of the derived plans, we employ a rule-guided, iter-
ative verification and refinement process. It checks
for: (a) the mutual independence of subtasks by
detecting overlapping uncertain factors, (b) the syn-
tactic correctness of the generated tree-structured

4.3 Logical Trajectory Collection
Based on the tree-structured plan of each subtask,
we use depth-first search (DFS) to extract the set
of decisionpaths. Each path, comprising multiple
query-response pairs, is considered as aconstraint.
The path sets from all subtasks are subsequently
integrated to form a set of logicaltrajectoriesfor
the entire task. Each trajectory, consisting of sev-
eral constraints, represents a possible situation that
agent may encounter. A direct integration approach
is via Cartesian product computation to enumerate
all trajectories. However, it can cause a combina-
torial explosion as trajectories scale exponentially
with the number of subtasks, necessitating compu-
tationally expensive simulations under excessive
environments. Furthermore, most trajectories fail
to introduce new constraints, making them redun-
dant in covering logical diversity.
To address this, we employ a heuristic Minimal
Trajectory Selection algorithm to eliminate redun-
dant trajectories while preserving a minimal subset
covering all constraints, as outlined in Algorithm
1. Specifically, we initialize an empty constraint
pool. Based on the logical trajectory set derived
from Cartesian product, we prioritize selecting tra-
jectories whose constituent constraints are entirely
disjoint from the current pool, while extracting
those exhibiting partial constraint non-overlap into
a candidate set. After each selection, its constituent
constraints are added to the pool. Finally, we check
the candidate set to select remaining trajectories
whose constraints have not yet been integrated into
the pool. An example is shown in Figure 3.
By constructing the tree-structured behavior
plans and collecting all logical trajectories, we
achieve a comprehensive capture of potential task
situations. This enables the logical diversity of
environments to be controlled at an abstract level.
Furthermore, the employed algorithm ensures di-
versity coverage with a minimal set of situations,
reducing redundant simulation and shortening the
testing cycle. The ablation and comparative results
(Sections 5.5.1 and 5.5.2) validate the efficacy of
the tree-structured plans and the algorithm.

4.4 Simulated Environment Construction
For each logical trajectory in the minimal set, we
create a text-based test case and instantiate it in
AI2-THOR (Kolve et al., 2017). Leveraging the
scene planning capability of LLMs, this process
is language-guided and can be deconstructed into
three stages: (a)Floor Plan Design, determining
room layouts and placements of doors and win-
dows; (b)Environment Object Selection, specifying
the environment objects and retrieving their corre-
sponding 3D assets; (c)Constraint-based Object
Arrangement, organizing objects based on designed
spatial relations and real-world physical rules.
4.4.1 Floor Plan Design
The floor plan defines the foundational structure of
the simulated environment, comprising three com-
ponents: rooms, doorways, and windows. Specif-
ically, each room is delineated as a rectangle by
its vertex coordinates and is characterized by its
floor/wall colors and materials. Doorways are spec-
ified by their types, sizes, and states (e.g.,opened,
closed). And windows are determined by attributes
like orientations (e.g.,west,east), types, and states.
4.4.2 Environment Object Selection
Objects serve as spatial infill and are grouped into
task-related and environmental enrichment types.
This grouping allows the environment to be tailored
to specific task requirements and trajectory con-
straints, while being enriched by integrating contex-
tually appropriate objects. Each object is defined by
properties like a textual description, assigned room,
size, and relevant attributes (e.g.,on_off_state).
Based on the textual descriptions (e.g.,“a brown
two-seater sofa”), we retrieve the corresponding
3D assets from Objaverse (Deitke et al., 2023b).
This retrieval process is automated through CLIP
(Radford et al., 2021) to match descriptions with
assets via text-image similarity scores, following
prior work such as Holodeck (Yang et al., 2024c).
4.4.3 Constraint-based Object Arrangement
Due to the inherent limitations of LLMs in numer-
ical reasoning, directly generating precise spatial
coordinates and orientations for multiple objects
often violates task requirements and physical prin-
ciples. To circumvent this, we utilize a hybrid
approach wherein LLMs first define high-level spa-
tial relation constraints, after which a computa-
tional constraint solver determines the final object
arrangements. This ensures that object placements
align with task-specific requirements and trajectory
constraints, while maintaining a coherent environ-
ment structure and adherence to physical laws.
We define four categories of spatial relations: (1)
Unary: edge, center, mounted on wall; (2) Contact:
in, on top of; (3) Distance: near, far; (4) Relative:
above, in front of, side of, center aligned, face to.
However, LLM-generated relations often show log-
ical inconsistencies (e.g.,“pen is in drawer”and
“pen is on top of bed”). To address such conflicts, we
employ a rule-based physical compatibility checker
to evaluate their plausibility. Detected inconsis-
tencies trigger iterative refinement, prompting the
LLM to revise its output based on feedback.
Subsequently, the object arrangement task is
modeled as a constraint satisfaction problem (CSP),
using the Z3 solver1 to compute solutions. Here,
object positions and directions (alongside doorway
and window positions) constitute variables. Spa-
tial relations and physical laws (e.g.,non-floating-
in-air,non-colliding) act as constraints. Notably,
if no solution satisfies all constraints, we adopt a
constraint relaxation mechanism. This selectively
disregards peripheral spatial relations, particularly
those involving environmental enrichment objects,
to prioritize essential task-related constraints. Sec-
tion 5.5.3 shows the efficacy of Z3 via ablation.

• Scenario Validity Rate (SceVR)This met-

• Fault Detection Rate (FauDR)This metric
measures the fault detection efficacy of the
generated simulated environments. Based on
150 faulty BTs of LogicEnvEval, we conduct
BT simulation in the generated environments
and compute the proportion of the revealed
faulty BTs. To ensure fairness, we exclude in-
valid test environments and only assess the ca-
pability of valid ones to reveal genuine faults.
This is because invalid environments invari-
ably report faults due to their configuration
errors, which is not effective fault detection.
For BT simulation, we employ a behavior sim-
ulator (Wang et al., 2025a) to efficiently execute
BTs and validate whether they are faulty. Besides,
we use Simulation Time (ST) to assess the time to
verify a BT on the generated test environments.

decision-tree-structured behavior plan explicitly or-
ganizes task logic to cover potential situations, fa-
cilitating logically diverse environment generation.

6 Conclusion
We propose LogicEnvGen, an LLM-driven frame-
work for the automated generation of logically
diverse simulated environments. Adopting a top-
down paradigm, we first capture all possible task
situations at the abstract logical level and then in-
stantiate concrete environment cases, thus yielding
broad coverage of the agent task decision paths.
Based on the proposed LogicEnvEval and the ex-
isting EMMOE-100 benchmark, we conduct quan-
titative evaluations across four metrics. The re-
sults demonstrate that LogicEnvGen exhibits strong
generalization, ensuring physical plausibility while
achieving significant improvements in logical di-
versity and fault detection effectiveness.
7 Limitations
We employ a behavior simulator to conduct BT sim-
ulation to measure the scenario validity rate and
fault detection rate of the generated environments.
We use this simulator for its high efficiency and
reliability. However, using general physics simula-
tors like Gazebo or Unreal Engine can yield more
high-fidelity evaluation results. This highlights the
need for future evaluation advancement.
Although we utilize a rule-guided iterative veri-
fication process to ensure the reliability of the gen-
erated behavior plans, relying on LLMs for auto-
mated generation remains susceptible to logical
omissions and misinterpretations. The assumption
that LLMs can capture complete task execution
logic from task descriptions may become fragile for
highly complex tasks. Future work can introduce
compensation mechanisms to mitigate these lim-
itations. One potential approach involves a critic
mechanism based on multi-agent debate to cross-
validate and refine the generated plan. In addi-
tion, integrating human-in-the-loop interventions
can better address challenging task scenarios and
improve the overall effectiveness of the method.
This work primarily focuses on complex condi-
tional tasks where agents need to actively gather
environmental information and dynamically adapt.
However, its applicability is limited in tasks involv-
ing strong coupling and strict sequential constraints
(e.g.,cooking a recipe), as well as in open-ended
environments characterized by fuzzy conditions
and continuous states.
8 Ethics Statement
We ensure our study aligns with the Code of Ethics.
However, as an LLM-based application, it may be
exploited by malicious individuals or affected by
the hallucinations introduced by the specific LLM,
which may generate misleading scenarios. We urge
users to apply our study responsibly.

A LogicEnvEval
In this section, we provide a detailed description
of the LogicEnvEval benchmark, which comprises
50 long-horizon household tasks featuring com-
plex conditional logic. To construct this dataset,
we first utilize LLMs to design diverse conditional
tasks (Bode et al., 2024) alongside their correspond-
ing ground-truth behavior plans structured as de-
cision trees. The task design principles focus on
reflecting common human needs in real world. Sub-
sequently, we equip every task with four distinct
agent policies represented as Behavior Trees (BTs).
These include one correct policy generated through
Code-BT (Zhang et al., 2025) and three faulty vari-
ations. Based on the existing taxonomy of faulty
BTs (Wang et al., 2025a), we construct these faulty
policies by altering nodes within the correct pol-
icy. Finally, we conduct multiple rounds of manual
verification and refinement to ensure the validity of
the task data.
The four agent policies are categorized based on
their adherence to physical and logical constraints.
To be specific, the faulty policy types include Coun-
terfactuals, Unreachable and Lackbranch. Coun-
terfactuals denotes that the BT violates real-world
causal logic (e.g.,taking an apple from a refrigera-
tor before opening it). Unreachable means that the
BT conforms to real-world logic but fails the task
goal (e.g.,merely grasping a book while the goal
is to clean it). The above two types consider all
possible task situations but fail in one, while Lack-
branch indicates that the BT omits some situations,
thus failing to adapt to diverse environments.

benchmark, we present a task exampleClean Liv-
ing Room, as shown in Table 7. The correct agent
policy is illustrated in Figure 6, while the three
faulty variations are visualized in Figures 7, 8 and

B Baseline Methods
Currently, there is no specific framework designed
for generating logically diverse test environments
for embodied agents. Thus, we compare LogicEn-
vGen with two environment generation methods,
Holodeck (Yang et al., 2024c) and I-Design (Çelen
et al., 2024), and two scenario-agnostic methods in-
cluding Chain of Thought (CoT) (Wei et al., 2022)
and IFG (Ahmed et al., 2025). Specifically, for
the CoT and IFG baselines, we generate text-based
test cases and then instantiate them in AI2-THOR
(Kolve et al., 2017), aligning with the implementa-
tion of our method. To ensure fairness, all methods
use the same problem setup, few-shot examples,
and asset library.
• CoT:We prompt LLMs to generate explicit
reasoning steps and subsequently design mul-
tiple test environments based on the embodied
task description to cover all potential task sit-
uations.
• IFG:IFG is a two-stage method that first sam-
ples intents and then generates responses to
promote semantic diversity of LLM output.
Following the official settings (Ahmed et al.,
2025), we set the LLM temperature to 1.1
during the intent stage to generate diverse log-
ical trajectories. Subsequently, we lower the
temperature to 0.5 during the final generation
stage to synthesize test environments condi-
tioned on the embodied task description and
the logical trajectories of the first stage.
• Holodeck:Holodeck is a language-guided
system capable of generating interactive 3D
environments from textual descriptions. We
provide Holodeck embodied task descriptions
to generate 3D environments.
• I-Design:I-Design leverages multi-agent col-
laboration to transform natural language de-
scriptions into plausible 3D interior designs.
We provide I-Design with embodied task
descriptions to construct simulated environ-
ments. Since I-Design is constrained to single-
room generation and lacks the capability to
design doors or windows, we adopt a generate-
and-stitch strategy to build multi-room envi-
ronments, enabling a unified evaluation with
other methods. Specifically, for multi-room
tasks, we invoke I-Design multiple times to
generate individual rooms independently and
then stitch them together in Blender.

Experimental results indicate that the LLMs

parameters. Notably, Gemini-2.5-Flash demon-

and Qwen2.5-72B, yielding consistent responses
in every run. Through in-depth analysis, we find
that LLMs are prone to several issues: incomplete
task decomposition, missing uncertain factors, and
incorrect uncertain factors. Specifically, the LLMs
occasionally group mutually independent subtasks
into a single subtask, resulting in the logically
redundant simulated environments. Furthermore,
when identifying uncertain environment factors,
the LLMs may overlook specific factors, leading to
missed branches; alternatively, they may consider
incorrect factors (e.g.,the existence or functional-
ity of an object), which undermine the validity of
simulated environments.
D Generation Efficiency
Excluding the rendering process, our pipeline re-
quires an average of 2.5 minutes per scene on a
single RTX 4090 GPU. This duration comprises
behavior plan derivation (approximately 25 sec-
onds), floor plan design (approximately 13 sec-
onds), environment object selection (approximately
45 seconds), and constraint-based object arrange-
ment (approximately 70 seconds). For comparison,
the generation processes of Holodeck (Yang et al.,
2024c) and I-Design (Çelen et al., 2024) require
approximately 2.3 and 3.7 minutes per scene, re-
spectively.
